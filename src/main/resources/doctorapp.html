Backend Assignment: "HealthSphere" — Zamonaviy Klinika Tizimi

Ushbu loyiha orqali siz Spring Boot, REST API, Spring Security, JPA/Hibernate, Concurrency (bir vaqtda yozishni oldini olish) va Transaction Management bo'yicha bilimlaringizni yuqori darajaga ko'tarasiz.

Siz ko'p tarmoqli klinika uchun shifokorlar qabuli, bemorlar tarixi, dorixona zaxirasi va to'lov tizimini o'z ichiga olgan murakkab backend yaratishingiz kerak.

1. Tizim Arxitekturasi va Entity'lar

1. User (Asosiy foydalanuvchi)

  • id (Long)
  • phoneNumber (String, unique - login uchun)
  • email (String, unique)
  • password (String, hashed)
  • role (Enum: ADMIN, DOCTOR, PATIENT, RECEPTIONIST, PHARMACIST)
  • isActive (Boolean)

2. Patient Profile (Bemor ma'lumotlari)

  • id (Long)
  • user (@OneToOne)
  • fullName (String)
  • dateOfBirth (LocalDate)
  • bloodGroup (Enum: A_POS, B_NEG, etc.)
  • allergies (String)

3. Doctor Profile (Shifokor ma'lumotlari)

  • id (Long)
  • user (@OneToOne)
  • fullName (String)
  • specialization (@ManyToOne Specialization)
  • experienceYears (Integer)
  • consultationFee (BigDecimal) - Ko'rik narxi
  • roomNumber (String)

4. Specialization (Yo'nalishlar)

  • id (Long)
  • name (String) - Kardiolog, Nevrolog va hk.
  • description (String)

5. DoctorSchedule (Shifokor ish grafigi)

  • id (Long)
  • doctor (@ManyToOne)
  • dayOfWeek (Enum: MONDAY...SUNDAY)
  • startTime (LocalTime)
  • endTime (LocalTime)
  • slotDuration (Integer) - Bemorga ajratiladigan vaqt (minut)

6. Appointment (Qabul/Band qilish)

  • id (Long)
  • patient (@ManyToOne)
  • doctor (@ManyToOne)
  • appointmentDate (LocalDate)
  • startTime (LocalTime)
  • endTime (LocalTime)
  • status (Enum: PENDING, CONFIRMED, CANCELLED, COMPLETED)
  • symptoms (String)

7. MedicalRecord (Tibbiy karta/Tarix)

  • id (Long)
  • appointment (@OneToOne) - Qaysi qabul asosida ochilgan
  • diagnosis (String) - Tashxis
  • notes (String) - Shifokor xulosasi
  • createdAt (LocalDateTime)

8. Medicine (Dori vositalari - Dorixona)

  • id (Long)
  • name (String)
  • manufacturer (String)
  • price (BigDecimal)
  • stockQuantity (Integer) - Ombordagi soni

9. Prescription (Retsept)

  • id (Long)
  • medicalRecord (@ManyToOne)
  • medicine (@ManyToOne)
  • dosage (String) - Kuniga necha mahal
  • durationDays (Integer) - Necha kun ichish kerak

10. Invoice (Hisob-faktura)

  • id (Long)
  • patient (@ManyToOne)
  • appointment (@OneToOne, nullable)
  • totalAmount (BigDecimal)
  • status (Enum: UNPAID, PARTIALLY_PAID, PAID)
  • issuedAt (LocalDateTime)

11. PaymentTransaction (To'lovlar)

  • id (Long)
  • invoice (@ManyToOne)
  • amount (BigDecimal)
  • paymentMethod (Enum: CASH, CARD, INSURANCE)
  • transactionDate (LocalDateTime)

2. REST API Logikasi va Endpointlar

🩺 1. Patient API (Bemorlar uchun)

GET /api/patients/doctors

Ruxsat: ROLE_PATIENT

Vazifasi: Mutaxassisligi bo'yicha shifokorlarni qidirish. (Filterlar: ?specialization=Kardiolog&maxFee=150000).

GET /api/patients/doctors/{doctorId}/slots

Ruxsat: ROLE_PATIENT

Vazifasi: Shifokorning ma'lum bir kundagi bo'sh vaqtlarini ko'rsatish.

Logika: Kiritilgan sana uchun DoctorSchedule dan ish vaqtini oladi. Keyin Appointment jadvalidan o'sha kundagi band qilingan vaqtlarni ayirib tashlab, faqat bo'sh (available) slotlarni qaytaradi.

POST /api/patients/appointments

Ruxsat: ROLE_PATIENT

Vazifasi: Shifokor qabuliga yozilish.

Logika (MURAKKAB): Bemor shifokor ID, sana va boshlanish vaqtini yuboradi. Baza darajasida aynan shu vaqtga boshqa odam yozilmaganligini tekshirish kerak (Concurrency check). Agar bo'sh bo'lsa, statusi PENDING bo'lgan yozuv yaratiladi.

👨‍⚕️ 2. Doctor API (Shifokorlar uchun)

GET /api/doctors/my-appointments

Ruxsat: ROLE_DOCTOR

Vazifasi: Shifokor o'zining bugungi va ertangi qabullarini ko'rishi.

Logika: Spring Security orqali joriy shifokorni aniqlab, faqat uning CONFIRMED qabullarini vaqt bo'yicha tartiblab qaytaradi.

POST /api/doctors/appointments/{id}/complete

Ruxsat: ROLE_DOCTOR

Vazifasi: Qabulni yakunlash, tashxis yozish va dori yozish.

Logika (TRANZAKSIYA): 1. Appointment statusi COMPLETED ga o'zgaradi. 2. Yangi MedicalRecord yaratiladi. 3. Array ichida kelgan har bir dori uchun Prescription qo'shiladi. 4. Avtomatik ravishda Invoice yaratiladi (Shifokor ko'rigi narxi qoshib qo'yiladi).

💊 3. Pharmacy API (Dorixona xodimi)

GET /api/pharmacy/prescriptions/{patientId}

Ruxsat: ROLE_PHARMACIST

Vazifasi: Bemorning oxirgi yozilgan retseptini va dorilar ro'yxatini ko'rish.

POST /api/pharmacy/dispense/{medicalRecordId}

Ruxsat: ROLE_PHARMACIST

Vazifasi: Shifokor yozib bergan dorilarni bemorga sotish.

Logika: Medicine jadvalidan stockQuantity (zaxira) yetarlimi tekshiradi. Zaxira yetsa, dori sonini kamaytiradi. Bemorning o'sha qabul uchun ochilgan Invoice iga dorilar narxini qo'shib qo'yadi.

💵 4. Reception & Billing API (Qabulxona xodimi)

POST /api/reception/invoices/{invoiceId}/pay

Ruxsat: ROLE_RECEPTIONIST

Vazifasi: Bemor klinika va dorilar uchun to'lov qilishi.

Logika: To'lov summasi kiritiladi. PaymentTransaction yaratiladi. Agar to'langan summa umumiy summaga teng bo'lsa, Invoice statusi PAID qilinadi.

📊 5. Admin Analytics (Boshqaruv)

GET /api/admin/reports/revenue

Ruxsat: ROLE_ADMIN

Vazifasi: Klinikaning tushumi bo'yicha hisobot (Parametrlar: ?startDate=...&endDate=...).

GET /api/admin/reports/doctor-performance

Ruxsat: ROLE_ADMIN

Vazifasi: Qaysi shifokor qancha bemor ko'rgani va qancha pul keltirganini aniqlash (Group By va Aggregation funksiyalaridan foydalaniladi).

🚀 Ushbu loyiha nimasi bilan qiyinroq? (Challenge)

  • Vaqt va Slotlar hisobi: Backend shifokor ish grafigiga qarab avtomatik ravishda ["09:00", "09:30", "10:00"...] shaklida bo'sh slotlarni generatsiya qilib berishi kerak.
  • Concurrency (Parallel so'rovlar): Agar bitta mashhur shifokorning ertangi 10:00 dagi bo'sh vaqtini bir paytda 2 ta bemor bosib (Booking) yuborsa, ularning faqat bittasi saqlanishi kerak (Optimistic Locking @Version orqali yechish tavsiya etiladi).
  • Kompleks Tranzaksiyalar: Dorixonadan dori sotish jarayonida pul hisoblanishi hamda ombordan dori ayirilishi kerak. Xato ketsa, hammasi orqaga qaytishi shart (Rollback).
  • Jadvallararo kuchli bog'liqlik: Appointment -> MedicalRecord -> Prescription -> Invoice zanjirini to'g'ri qurish.
